## Paper and claim
- **Target:** SEAMS 2027 research track (Oct 23 AoE; IEEE, 10 pages + 2 of references, double-anonymous), mainly for the reviews, then ICAPS 2027 (Dec 7 abstract), where generalized policies are a core topic. Gridworld and Pac-Man first; benchmark-set families and PAYNT only if time allows (Asher). Write first, then finish. Rajan helps with implementation.
- **Story (Asher):** the LLM writes a generic strategy, and the verifier refines it (feedback, and the order that resolves `any` rules) and certifies it on every held-out instance.
- **Claim:** one readable controller for a parametric family of instances, with probabilistic guarantees checked per instance: "certified on every instance we check, including held-out larger ones", never "correct for all sizes" or "maximally permissive". What to say and not say: `docs/positioning.md`.
- **SEAMS angle:** a library of frozen rule sets, certified at run time on the instance met; the system adapts by switching to one that certifies (the "library" metric in RQ1).
- **The paper's Approach presents the production loop, not the test protocol** (Asher, Oct 18): the library is seeded offline from small training sets and grows at run time; when no list certifies on the instance met, synthesis runs on that instance plus the training set of the closest list, and the result is deployed and added. Not implemented as a system; the evaluation approximates it by certifying a seeded library on held-out instances, without the extension.
- **Adaptation policy** (after Marsha's Oct 18 review, which reframed the paper around certified reuse and replacement; Asher, Oct 19): the manager adapts between episodes (certificates hold from the initial state); it retains a certified current rule list before searching the library, otherwise selects the certified library list with the largest smallest margin, otherwise generates; if the generated list is not certified on the instance, adaptation fails and the episode is deferred (no safe fallback is claimed). An interval-iteration result whose bounds straddle the threshold counts as not certified.
- **SEAMS reports validation numbers only**, labelled as such; the test set stays sealed through SEAMS (Asher, Oct 15).
- **Figures show each method's best configuration** (chosen on validation, never re-chosen on test results); tables show every configuration (`docs/experiments.md`).
- **Option B (the LLM also writes the model) is parked** (Marsha): with model and policy both written by the LLM, a failure can't be attributed and there is no ground truth; it would also compete with LLM-as-domain-generator work and split effort.
- **The domain provides the rule vocabulary.** The LLM-written vocabulary (branch `rule-language-generation`) is parked: two moving parts at once would make results unreadable (Asher).
- **The bar:** the closest work is 1–2–3–Go! (trees over raw state variables, learned on small instances, certified per larger instance). Its trees over raw variables fail on our families, so the honest bar is the hand-written template, the best searched rule list and 1–2–3–Go!'s trees over our features.

## Method
- **Kickoff choices:** one LLM call over the whole state space (no per-goal decomposition); rules form an ordered decision list, first match wins; feedback locates states and rules but never reveals PRISM's optimal action.
- **Success means every requirement holds in the worst case** over all completions of the rules (a sound permissive strategy); the best case is reported separately. REFINE when no completion can pass, EXTEND (append) otherwise; keep-best by (worst failures, best failures, worst shortfall, best shortfall). Spec: `docs/semantics.md`.
- **Blame by probability mass:** expected visits within H steps × probability still at stake. V^opt stays in the loop (Marsha); one-step regret is an ablation. Rejected: a performance-difference decomposition, which gives about 0 mass when the adversary stalls the agent in loops through uncovered states (the main failure mode), because without discounting its residual term does not vanish.
- **Feedback names states by coordinates in the core** (`feedback.space: states`; Asher, Oct 15). Feature space (`features`, no positions) was tested as the core candidate and lost: over 5 runs it certifies fewer validation targets per list on grids (−0.50 [−0.90, −0.10]) and families (−2.13 [−5.20, +1.00]), and is level on Pac-Man. Coordinates did not lead to position rules, so it had nothing to remove (`out/results/experiments/rq2_verifier_output/FEATURE_SPACE.md`). It stays an RQ2b ablation cell. A variant naming states relative to the next goal and the moving obstacle is untested.
- **Rule language** (`docs/semantics.md`, "Extended vocabulary"): instance constants, domain features, `any` rules and general mode, after generalized planning (Fern, Yoon and Givan; Martín and Geffner; Bonet, Francès and Geffner). Rules over absolute coordinates cannot transfer. General mode does not stop instance-specific rules: relations between constants (`G2R = G3R + 1`) and offsets (`G2C - 1`) still single out instances.
- **Multi-instance training** (`run.train_sets`): rules written for one grid overfit to it, even in general mode, so one rule list is written for and verified on several instances each round.
- **`any` resolved in the loop** (`rules.any_order`): each round the verifier picks the action order that does best on the training members. It gave the transfer search's best validation numbers, where prompting changes did not move them. Whether the solver may choose is open (below).
- **Core configuration** (Asher, Oct 16: the rebuilt loop replaces the previous one): the `port_*` conditions (next item), on Pac-Man with verifier narrowing (`port_pacman_narrow_core`), on random grids and families with the fixed failure reading and repair (`port_ts_history`, `port_fam_history`; Asher, Oct 17: entering the next goal in its turn no longer reads as the failure; the unfixed runs are in `rq2_previous_loop`). Core runs are the RQ1 cells, in `out/results/core/`; other runs go to `out/results/ablations/`, baselines to `out/results/baselines/`. The previous loop (multi-instance training, the generality instruction, no restarts, `rules.any_order: all`, Pac-Man `rotations`) is compared in `rq2_previous_loop`; the other RQ2 pages still ablate the previous loop. If memory is ever added to the rule language, its conditions and runs get a `-memory` suffix (Asher).
- **The clean-slate loop is our best configuration** (Oct 16-17; the `port_*` conditions: `rules.strict`, `prompt.worst_case`, `planner.feedback: failures`, `planner.chains`, `planner.pick`, `planner.repair`; `docs/semantics.md`). A session rebuilt the loop from symbolic-policies without seeing this branch's transfer code (its results and code are on branch `fresh-transfer` (tag `fresh-transfer-oct16`; `out/fresh/RESULTS.md` there); the runnable version is branch `fresh-transfer`, tag `fresh-transfer-oct16`, on origin), and it was then ported. Transfer tracks whether the training set is solved (families: 14.2 certified per solved list against 5.2), and the old loop rarely solved rooms, crossing or MER across x; this one solves them: families 19.44 per list (fresh code; the port's first clean repeat 18.33), random grids 7.92, both MER benchmarks 6/6, Pac-Man 4/6 with narrowing (RQ1 report). It does not help without `closer` (3.5-3.7 against the template's 6). Repair adds little in the fresh code (families without it 17.11; MER and Pac-Man unchanged) but stays: in the port, the families lists picked without it transfer worse and vary more (the runs' `transfer_*_norepair*.csv`). Letting the verifier choose `any`'s order every round does worse (16.00) than keeping `any` open and resolving it once in the pick.
- **Gridworld features:**
  - `collide` (opt-in, `rules.extra_features`: the move or a slip of it can end where the moving obstacle goes next) was found by analysing the failures of frozen family lists on validation members (Oct 16); say so if it is used. It stays an ablation: it also lifts the trees over our features (12.33 -> 15.00), and the fresh method gets 18.33 without it (orchestrator).
  - `closer` (shortest path through free cells) routes through the patrol only where no other route exists (each patrol cell costs n·n): family members whose only passage crosses the patrol need it.
  - `closer` stays in the configuration we claim, for now (Asher, Oct 15). Removing it may be tried again later, so the no-`closer` benchmark (`grids_noclose`) and ablation cells stay; `docs/positioning.md` (Check 1) has the case against it.
  - `hazard` is the union of `patrol` and `early`. The split exists because Haiku wrote `!hazard` into every rule and never crossed a patrol, which the crossing and rooms families need.
  - Conditions that predate a feature hide it (`rules.hidden_features`), so their prompts stay those of their runs.
- **Output and parsing:** JSON-schema structured output with the actions as an enum, capped at 64 rules and 200-character conditions (without the caps qwen falls into repetition loops). Parsing accepts common LLM spellings (`==`, `&&`, `and`, a trailing `-> action`). An invalid answer is re-asked with the error up to 2 times; after that the round counts as an empty policy. Rule listings and examples use the answer's JSON-per-line shape, because qwen copies the notation of examples into conditions.
- **First-match compilation:** each rule's guard negates only the earlier rules that can overlap it (found by enumeration up to 200k valuations), so 500-rule legacy policies stay compact.
- **The default prompt keeps the catch-all instruction and example** (`prompt.*`): with qwen, removing the example halved the catch-all rules, and partial policies lose under the worst case.
- **Default retry `gain:0.05`** (start over when the last round cut total worst-case shortfall by less than 0.05, so after any round without improvement): it won the qwen retry sweep. B2 and the conditions compared with it use `stall:2`.
- **Forced states** (every policy-labelled choice has the same successor distribution) are not situations: no rule can change them, so they are left out of coverage, hotspots and blame. Decision states count only choices labelled with a policy action; Pac-Man's unlabelled arbiter step is environment nondeterminism.
- **Reward requirements** (`R{r}` bounds): shortfalls and blame stakes are relative to the threshold, so energy does not swamp the probabilities; infinite expected rewards are capped in the mass analysis; prompts mention cost only when a reward requirement fails.
- **Seeds:** each call's seed derives from the run seed and the call's index (`seed * 1_000_003 + n`), since one fixed seed made every repeat of a prompt return the same answer. Claude endpoints take no seed, so their repeats are unseeded (`--unseeded N`).

## Solvers and numerics
- **Gauss-Seidel in the loop** (`prism.method`): rules that read `obs_idx` can make the induced chain periodic, where plain value iteration does not converge. Fallback: modified policy iteration (a real qwen rule set converged with neither Gauss-Seidel nor plain policy iteration). If every method fails, the round scores as an empty policy.
- **Exact solvers: interval iteration, then PRISM's linear programming where it stalls** (Asher, Oct 19; `prism.exact_methods`, in the final check, `src/transfer.py`'s re-check near a threshold, `src/recertify.py` and the sequential study). Interval iteration never converged on 32 crossing-family checks (`avoid_moving_seg3`), which the paper tables then counted as failures (families 17.44 -> 13.89 per list). LP certifies all 32 in seconds, as does the numpy checker, but has no error bound: it differed from interval iteration by up to 1.0e-4 where both finished, so its margins within `prism.lp_tolerance` (1e-3) are inconclusive. Interval iteration stays first for its error bound and stops at `prism.ii_max_iters` (10^6). The final checks are `transfer_exact_*.csv` (`recertify.py combine` of the interval-iteration and LP checks).
  - **Correction (Oct 21): the LP stage never ran.** PRISM 4.10.1 switches `-lp` to Gauss-Seidel for these properties, so the 1,347 checks interval iteration did not decide had no error bound. Every verdict the paper and Rajan's report use is now one rule and one file (`src/certs.py` -> `out/paper/certs.csv`: interval iteration, then Storm `--sound`/`--exact`; no LP or Gauss-Seidel), which every table reads; 32 verdicts changed (`out/paper/RESULTS-NOTES.md`, "Oct 21 night").
- **Exact check of the final policy** (Asher): interval iteration at 1e-9 (then LP where it stalls, since Oct 19, above), or Gauss-Seidel at 1e-12. Gauss-Seidel stops when an iteration changes little, which bounds nothing: on a slowly leaking chain it reported a `goal3` of 0.587 whose exact value is 0.799. The loop keeps Gauss-Seidel because interval iteration takes minutes on such chains and the loop only needs a ranking.
- **Choosing the order for `any` rules, faster** (`rules.any_order`; Oct 15). Most of a round was PRISM verifying 24 orders on each member. Measured on every recorded gridworld round of the core and ablation runs (2,113 rounds, 129 runs):
  - *Same model, verified once* (always on, no key): an order that resolves the rules into the same action as an already verified order at every state reachable under that order gets the same PRISM model, so it takes its values. It skips 19% of the checks on the core runs (grids 18%, families 21%). Requiring the same action over the whole visible space would skip only 9%: in 329 of 408 member-rounds all 24 orders differ there.
  - *`rules.any_prune`* (off; the run store ignores it): the numpy gridworld (`RuleScorer`) rules out the orders that cannot score best if PRISM's values are within 1e-3 of the exact ones; PRISM verifies the rest, and every order when a verified one is off by more. It leaves about 36% of the order checks (core grids 45%, families 34%, before the dedupe). It picks the recorded order in every round: in 2,112 the recorded order survives the pruning, and in the other (`core/haiku_ts_order_noclose/seed_none_3`, set0, round 5) Gauss-Seidel scored the order numpy prefers at 6 failures where interval iteration and numpy find 4, so the check fires and every order is verified. The guarantee is conditional: an order ruled out is never verified, so if the loop's solver were off by more than 1e-3 on such an order only, the choice could differ. Domains without a fast model (Pac-Man) only get the dedupe.
  - *`rules.any_scorer: domain`* (off; the store counts it): numpy ranks every order and PRISM verifies only the chosen one. It chooses another order in 567 of the 2,113 rounds, 546 of them exact ties (to 1e-9) between orders that differ only where the choice does not matter, which Gauss-Seidel's error breaks. So it is a different configuration.
  - *Timing* (saved answers replayed, prompts, rules and orders identical to the saved runs in every round; order checks / wall time): a grid training set (`core/haiku_ts_order/seed_none_1`, set1, 3 rounds) 216 / 701 s before, 180 / 452 s with the dedupe, 35 / 203 s with `any_prune`; a family set (`core/haiku_fam_order/seed_none_1`, set0, 5 rounds) 360 / 774 s, 268 / 515 s, 100 / 405 s (one round fell back to every order). Wall times ran under different loads; at equal load the checks set the time.
  - **[REVIEW]** The loop's solver decides some choices. Gauss-Seidel is within 1e-4 of the exact value in 89% of rounds, but off by more than 1e-3 in 138 (up to 0.91). Exact values (`any_scorer: domain`, or interval iteration for the orders) would choose by the true scores, at the cost of new runs.
- **One fast checker for every domain** (Asher, Oct 25; `src/core/checker.py`, the default `Domain.fast_checker`): repair, the pick's order and narrowing score lists on the model PRISM exports, with each formula turned into an automaton by progression and its worst case solved exactly (Prob0A/E, then policy iteration). It replaces gridworld's own checker (`GridChecker`) and the value iteration Pac-Man and MER used; on the test instances it agrees with both to 1.2e-12, at the same time per list (`tests/test_fast_checkers.py`). Rewards and step bounds are unsupported, so UUV gets none.
- **Joint queries use exact LP.** LP cannot do step-bounded objectives, so for UUV the joint query is undecided and the loop uses the per-requirement branch.
- **Timeouts:** on Windows, killing `prism.bat` leaves its JVM running, so `PrismRunner` kills the process tree. A joint query that times out is undecided.
- **Regression** (`src/regression.py`): the symbolic gridworld MDP equals the legacy DTMC to 5e-10 over 100 legacy policies. It uses interval iteration because at default settings the worst case of nested-until properties stops early, by up to 4e-3.

## Running and comparing
- **Feedback must beat resampling at equal cost, on the same plot** (Marsha). A budget curve that rises every round is guaranteed by keep-best, so it is no evidence for feedback, and feedback rounds cost more tokens than fresh ones, so equal rounds is not equal cost. With qwen on small grids, resampling was level or ahead. With Haiku 5.5 on `grid_20_large`, feedback beat it in all four comparisons fixed before the runs (`out/results/archive/haiku_large/SUMMARY.md`).
- **The new loop's feedback against pure restarts** (Oct 17; `out/results/experiments/rq2_restarts/REPORT.md`): on the families feedback certifies 17.44 per list against 13.67 for restarts, and 15.67 at the restarts' two-thirds spend (`src/equal_spend.py`); on MER across x both certify 6 of 6, and feedback at the restarts' spend 5.00.
- **Ablation model and dataset: Haiku 5.5 on `grid_20_large`** (Asher). Sonnet 5.5 solves every solvable `grid_20_balanced` grid, most in round 1, and 13x13 grids too, which leaves no headroom; qwen's results are limited by the model, not the loop (`out/results/archive/sonnet_vs_qwen/SUMMARY.md`).
- **OpenRouter runs are a condition of their own** (Asher): hosted weights (FP8/BF16) and seeds differ from the local 4-bit model. Pin a provider (`llm.openrouter.providers`) and name model, provider and quantization in results. Every request requires the schema and seed parameters.
- **Tokens are the cost measure.** Wall-clock times are not comparable across schedulers or between parallel and sequential runs.
- **Haiku only for now** (Asher, Oct 15): no Sonnet runs until we truly think we have found an improvement or the final method; then ask Asher, each time. Sonnet cells keep `launch: false`.
  - Oct 16, at Asher's request: Sonnet 5.5 with the old core configuration on every benchmark (3 runs each). It beats Haiku on families, both MER benchmarks and grids, not on Pac-Man or without `closer`, beats the best baseline only on grids and families, and cost about $26 of a $30 weekly budget (RQ1 report). If Sonnet does better, the final method is the new loop run with Sonnet (Asher); with Haiku the new loop is already near the ceiling on families and grids, so it is run with Haiku.
- **Legacy baseline:** the predecessor's planner (`src/legacy/`, gridworld only), changed only for fairness (obstacle visibility). Same model, grids and rounds as symbolic; the prompts differ by design (legacy has worked examples). Legacy runs on qwen only: one call per goal and obstacle phase per round would be expensive on a hosted model. The predecessor's other planners are on `main`.
- **The planner is a generator** (it yields LLM tasks and PRISM calls), chosen over a blocking client behind a barrier, a state machine or asyncio: the loop reads top to bottom, each batch is an explicit list, and it cannot deadlock. If pausing inside an instance (crash recovery) is ever needed, its locals can move into a state object without changing schedulers or backends. `docs/scheduler.md`.
- **Config:** one folder per tool, and each `default.yaml` is the only place its defaults live (Asher). `docs/config.md`.

## Case studies
- **Gridworld:** a symbolic PRISM template (formulas for move, slip and bounce) rather than enumerated cells. `grid_20_balanced` is the first 4 grids of each size 4–8 of `grid_50_balanced`; the other datasets and splits are in `docs/experiments.md`.
- **UUV** (Päßler et al., iFM 2023):
  - The MDP follows the paper's ProFeat artifact, not the extended model on that repository's main branch.
  - Visibility limits are modelled by clamping, so every action is enabled everywhere and each state's distinct choices are exactly the paper's.
  - The policy sees what the paper's controller monitors (`s`, `alt`, `water_visib`).
  - The description lists the integer levels of each visibility band, because qwen copied decimal thresholds into conditions, which the integer rule language rejects.
  - The mass horizon is the mission deadline (`feedback.horizon: domain`, Asher).
  - PRISM's multi-objective query understates a concrete policy's value (0.795 vs 0.807), so calibration does not use it.
- **Pac-Man** (QVBS `pacman`, version 2): the benchmark's model with `MAXSTEPS` set per instance, chosen because 1–2–3–Go! fails on it and its choices are labelled actions. Requirement: crash ≤ 0.56 (the optimum is 0.5511 at every horizon). The loop trains on short horizons; longer ones only certify frozen rules. The 1–2–3–Go! artifact holds no Pac-Man values, so we compare with its published ones (0.869 at horizon 25).
  - **The threshold stays 0.56 at every horizon** and certified counts use it (Asher, Oct 15). Since our rules certify nothing beyond horizon 18 at 0.56 (1–2–3–Go!'s tree trained on 14–18 certifies 20, nothing certifies 25 or 30), the Pac-Man headline is the worst-case crash probability against the horizon (ours, 1–2–3–Go! reimplemented, PPO, the optimum, 1–2–3–Go!'s published points; `horizon_figure` in RQ1).
  - **Beyond the training horizons** (Oct 16): solved lists fail from 20 because late in the game they walk into the dead end at (3,4), which games of 14-18 moves never punish. The verifier may now keep such a move away from its place (`rules.early_narrow`, judged on the first half of the training games, as 1-2-3-Go!'s data): every solved list then certifies 20; Haiku given the same information as feedback did not make these narrow edits (`out/results/ablations/pacman_horizons.md`; with the port, narrowing certifies 4 of 6 in every run, the port alone and its feedback-only twin 3). **[REVIEW]** the verifier editing the LLM's rules (below).
  - **Horizons 5, 30, 50 and 100 join `pacman_transfer.csv`** (Asher, Oct 15): 50 and 100 are sealed as Pac-Man's test set, 30 is a validation target. 5 is 1-2-3-Go!'s training instance and no validation target: every policy gets 0.5511 there (the bare model's minimum equals its maximum), so it would add one free certificate to every method. 200 was dropped: PRISM cannot build its model (it runs out of a 4 GB heap past 13.8M states on 50 already; `docs/experiments.md`). **[REVIEW]** 50 and 100 stay sealed as Asher decided. The bare model cannot be built there, so the per-state baselines (PPO, random, one-instance, uniform) cannot be certified on them. A frozen rule list's model is much smaller (a Haiku list: 29k states at 30, growing about 2.8x per 5 moves, so roughly 0.6-2M at 50, which fits in memory), but its check took 195 s at 30, growing 2.3x per 5 moves: about 1.5-3 hours at 50, beyond the 900 s timeout. So the test pass on 50 needs a longer timeout per list; 100 is probably out of reach. Asher's call at the test pass.

- **No harder benchmark among the QVBS families** (Oct 16, before any LLM run). The one that fits our framework, consensus across the random walk bound K at N = 3 (requirement `disagree`; `domains/consensus/`), leaves no headroom: trees over the raw variables, the uniform policy and the strategy of K = 4 certify none of the six validation instances, but 1-2-3-Go!'s trees over our features (barrier distances, decided values, each process's stage and coin) certify all six at 99.9% of the optimum, so as on Mars rovers we could only tie (`domains/README.md`). Removing features until the tree fails would tune the vocabulary against a baseline. The others do not fit: csma (at N = 2 every scheduler gets the same value; at N = 3 the instances PRISM can build stop near K = 4, where the worst scheduler already passes: 0.905 against 0.95 x 0.932), resource-gathering (step-bounded properties), wlan and zeroconf (trivial, or near-optimal for 1-2-3-Go!), the IPPC models (object-parameterized, mostly optimum 1), and the families that add processes with N.

## Open questions
- **[REVIEW] The solver choosing among versions of the LLM's output** (`rules.any_order`, polishing, counterexamples, narrowing: `rules.early_narrow`). Asher would prefer the solver only to give feedback, so that the framework carries over to other solvers; it may choose unless Marsha decides otherwise. Its contribution to a frozen list is one action order out of 24, chosen on the training members (`src/tie_analysis.py`; "ties open" in RQ1). RQ2 (`rq2_choices`) compares the feedback-only variants (`declared`, `report`); on the crossing family, the variants without the solver's choice of order certify about 0 of 20.
- **[REVIEW] The "why LLMs" claim.** With `closer`, short generic lists exist: a 2-rule list found without an LLM certifies 7 of 8 validation grids. If the search matches the LLM on validation, the story changes.
- **[REVIEW] Reused runs may come from older code.** The run store assumes every behaviour change comes with a config key, which holds on this branch as far as I can tell. The worst-case cells reuse runs made before in-loop order resolution existed; with `any_order: none` that code path is the same.
- **[REVIEW] UUV.**
  - The failure-rate family is trivial (`stay` covers every member): drop it, or find a family where no simple policy passes (vary visibility ranges, deadlines, inspection lengths), checked with PRISM before any LLM run.
  - Thresholds are tight by design: looser ones would let any sensible complete policy pass. The energy thresholds and the description of energy costs need a look. Neither qwen nor Sonnet 5.5 solved the Caribbean scenario, which `stay` passes.
  - Two ideas from the archived `optimization` branch need a decision: listing every previous attempt's worst case in the feedback (no help on UUV, untested on gridworld), and hiding `water_visib` (qwen then writes hold-the-altitude rules, but the policy would no longer see what the paper's controller monitors).
- **[REVIEW] Smaller items:** the joint branch applies to gridworld but not UUV; the S5 (regret) prompt wording; the wording of legacy's obstacle-phase note; legacy's solver fallbacks are untested on a real non-converging case; `event` is the default scheduler for symbolic runs (`run.scheduler=threads` to compare timings with threaded runs).
- **Open:**
  - QVBS families through the 1–2–3–Go! artifact (`third_party/README.md`; Docker or WSL): reproduce two of its published numbers, then pick one family it fails on (csma or Mars rovers) and one it does well on. Mars rovers is a domain now (`domains/mer/`, over x as in the paper); it reproduces four published optima. **[REVIEW]** It is not a family where 1-2-3-Go! must fail, across x or across n (`mer_n_transfer.csv`, x = 0.89): its raw-variable trees certify every held-out instance once trained on several instances (n = 10 for x; n = 1, 2, 3 for n) and fail only from the paper's single base instance n = 1. Haiku: 2.4 of 6 on both, with 2 of 5 runs optimal on every n (RQ1 report, both Mars Exploration Rovers sections); the new loop: 6/6 on both, a tie. From the paper's single base instance (`mer_one`, `mer_n_one`, every method trained on n = 1 only; Oct 17) everything ties too: ours, the trees and the strategy of that instance 4 of 8 across x, every method 0 across n, since what is optimal at n = 1 tries the arbiter's shortcut once. Pick another family for the "must win" case. Each becomes a domain with a test that reproduces a published value, a vocabulary and thresholds: the optimum plus 5% of it per instance, minus 5% when maximizing (Asher, Oct 15).
  - Families of MDPs (PAYNT): robust per-state policies on a same-size gridworld subfamily against our rules on held-out grids of that size. It does not apply across sizes, so it is a positioning experiment.
  - The strategy of one instance applied to the others (Marsha's baseline) exists for Pac-Man (`src/baselines/simple.py`, any domain); not yet for gridworld.
  - Untried ideas: a closed patch language (variables compared with constants only), best-of-N first rounds, rotating the shown members each round, and starting the training-set loop from what a run's per-grid rule sets share.
  - Readability (rules against tree nodes and network weights) has no metric.
  - Prompt wart: gridworld's `description.md.j2` runs two bullets together ("it starts at 0.- The agent keeps moving"). Fixing it changes every gridworld prompt and the saved-run replays, so it waits for a deliberate prompt revision.
  - Which batched serving engine to target; only the interface is general (`BackendInfo.max_batch`, `supports_schema`, `supports_seed`).
