# Baseline configs

One file per baseline run of `src/run_baseline.py` (methods in `src/baselines/`). Results go to `out/results/baselines/<file stem>/transfer_<dataset stem>.csv`, in `src/transfer.py`'s format plus `method`, and `fit.json` for methods that report what their fit produced (e.g. a tree's size and rules).

| Key | What it does |
|---|---|
| `method` | the baseline (`src/baselines/__init__.py`, `METHODS`) |
| `condition` | run condition whose rule language (`rules.*`) and PRISM settings apply; `null` = the default run config |
| `dataset` | instances, as in a run config |
| `target_dataset` | the targets' dataset, when it differs from `dataset` (e.g. a sealed test set); `null` = the same. Then no target counts as trained |
| `train` | ids of the training instances (`"0-11"`, `"0,4,8"`); `""` for methods that are not fitted |
| `targets` | ids of the instances to certify on |
| `workers` | targets checked at once |
| `exact_near` | re-check with the exact solvers when a worst case is within this of its threshold (0: never) |
| `params` | the method's own settings (its module docstring) |

`params.model: explicit` (`decision_tree`, `ppo`) runs a method on any domain, from the explicit models PRISM exports (`src/baselines/explicit_mdp.py`); without it they are the gridworld versions. The methods `uniform`, `random_policies` and `one_instance` (`src/baselines/simple.py`) work on any domain too. Per-state policies (PPO, `simple.py`) are certified on each target's explicit model, one target at a time (a model of millions of states takes gigabytes), so `workers` does not apply to them.

Pac-Man (`pacman_*.yaml`, condition `pacman_baseline`: extended vocabulary, numbers allowed): trees over raw variables and over our features, each trained on horizon 5 and on horizons 14-18 (`pacman_tree_raw`, `pacman_tree_features`); PPO over raw variables and over our features, three seeds (`pacman_ppo_raw`, `pacman_ppo_features`); `pacman_uniform`, `pacman_random_policies`, `pacman_one_instance` (horizon 18's strategy, aligned by moves made or by moves left); the hand-written maze rules. All are certified on ids 0-9: the validation horizons (RQ1 counts ids 0-7 and 9) and horizon 5 (id 8), 1-2-3-Go!'s training instance, where every policy gets 0.5511. Ids 10 and 11 (horizons 50, 100) are sealed.

Mars Exploration Rovers (`mer_*.yaml`, condition `mer_baseline`: extended vocabulary, numbers allowed): trees over raw variables and over our features (`shortcuts_left`, `enabled`), each trained on n = 1, x = 0.01 (id 7, the paper's training instance) and on our training set (ids 0-2: x = 0.01, 0.05, 0.13 at n = 10) (`mer_tree_raw`, `mer_tree_features`); PPO over raw variables and over our features, three seeds (`mer_ppo_raw`, `mer_ppo_features`); `mer_uniform`, `mer_random_policies`, `mer_one_instance` (the strategy of x = 0.13). All are certified on ids 0-8; ids 9-11 are sealed. The family across n (`mer_n_*.yaml`, x = 0.89, mer_n_transfer.csv) has the same baselines: trees trained on n = 1 (the paper's base instance) and on n = 1, 2, 3, and the strategy of n = 3 looked up by `k` or by `shortcuts_left`. In mer an action that is not possible leaves the state unchanged, a self-loop, whose value always equals the state's. So when maximizing, `ExplicitMDP.optimal_actions` counts an action as optimal only if it also leads towards the target (as Storm's schedulers do); otherwise the trees and the one-instance strategy learn to wait. A policy that waits in the initial state leaves a one-state model, which PRISM cannot import; `certify` takes its value from numpy.

Mars Exploration Rovers trained on one instance (RQ1 `mer_one`, `mer_n_one`, as 1-2-3-Go!'s paper: n = 1, id 7 of `mer_transfer.csv` and id 0 of `mer_n_transfer.csv`): the trees trained on n = 1 come from `mer_tree_raw`, `mer_tree_features`, `mer_n_tree_raw` and `mer_n_tree_features` (sources `tree_raw_n1`, `tree_features_n1`), the uniform policy from `mer_uniform` and `mer_n_uniform` (no training); `mer_one_*.yaml` and `mer_n_one_*.yaml` add what depends on the training set: best of 1000 random policies ranked on the one instance, the strategy of that instance (looked up by `k` or `shortcuts_left`) and PPO over raw variables and over our features (three seeds). All are certified on ids 0-8.

Randomised consensus (`consensus_*.yaml`, condition `consensus_baseline`: extended vocabulary, numbers allowed), across K at N = 3, the screening of a candidate benchmark (not in RQ1; `domains/README.md`): trees over raw variables and over our features (`to_heads`, `to_tails`, `heads_decided`, `tails_decided`, per action `finished`, `stage` and `coin`), each trained on K = 2 (id 0, the smallest instance) and on K = 2, 3, 4 (ids 0-2) (`consensus_tree_raw`, `consensus_tree_features`); `consensus_uniform`; `consensus_one_instance` (the strategy of K = 4 looked up by the counter, by `to_heads` or by `to_tails`). All are certified on ids 0-8; ids 9-11 (K = 24, 32, 48) are sealed. A finished process's label moves the next one, so no action is a self-loop here.
